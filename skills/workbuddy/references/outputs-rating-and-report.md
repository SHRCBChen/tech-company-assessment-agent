# 成果、评级与报告

## 四类成果边界

### Excel

面向客户经理，只保留企业/项目标识列、11类事实字段和最后一列“公开风险事项”。风险列只填`有`或`无`；不放评级、来源、日志、参保/员工人数或方法说明。核心人员联系方式仅保留明确归属于具体核心人员的公开直联方式。

“主要产品”不能只列产品名：用简洁文字解释产品形态、核心组成或工作方式、解决的问题和下游用途。“核心技术及应用场景”写清技术路线、可核技术指标和应用场景，并补充同类主流企业/产品的发展概况，以及可比的性能、成本、功耗、集成度、交付方式或适配范围差异。没有可靠数据时只写比较维度和公开可确认差异，不编造参数。

“公开风险事项”以企查查等可靠工商司法渠道对目标企业自身风险的核验为准，排除关联公司、股东个人或仅属历史提示的关联风险。`无`只表示本次查询时点和限定公开渠道未发现目标企业自身风险；该说明保留在Skill和事实底稿，不重复塞进Excel。

### ima当前事实底稿

内部证据与知识问答使用，一家企业一条可编辑ima笔记；本地仍生成一份Markdown作为发布源。包含主体映射、现场笔记原文及忠实拆解、全部有效原子事实、来源标题/URL/日期/类型、每个来源的`supports`与`cannot_support`、冲突、待核项和旧主张去向。不是Excel摘要。

可保留A/B/C/D评级、一句客观理由和现场笔记明确记载的一条简短评委意见。不要放完整评价、拜访重点或建联建议；没有现场意见时直接省略，不写“暂无”。Agent正式启用前不写受众、schema/file版本或版本记录。

### 企业初评报告

面向客户经理，目标1—2页。覆盖11类信息但可合并章节；不按Excel列逐项复制，不使用`标签｜事实`罗列，也不能只把标签换成句号。沿用既有章节结构，不因内容丰满而另创章节。

报告追求判断精度，不追求事实数量。11类字段是信息池，不是11个等权评分项；覆盖不等于平均展开。先选出会影响企业潜力和调研优先级的关键事实，再建立要素关系。

推荐逻辑：

1. 产品解决的问题、技术路线和应用场景。
2. 核心团队及研发支撑，包括资质、科技项目和知识产权。
3. 产业化阶段、客户证据、产业链位置和竞争环境。
4. 融资/股权时间线、逐家机构背景、资本组合及可验证的产业资源。
5. 大赛现场笔记带来的关键增量。
6. 最后一节“综合评价与拜访重点”：先形成一段综合判断，再列与关键约束一一对应的拜访问题。

每段只表达一个中心判断并由客观事实支撑，同一事实不在多章重复。无信息时直接省略，不写空白说明；不单设“建联切入点”，校友、导师或机构关系仅在确有价值时自然融入团队或拜访重点。社保/员工人数不进入报告。

允许形成明确的负面判断。若需求证据、商业路径、技术差异化或团队支撑明显不足，可以直接写“现阶段不宜优先调研”“需求成立性较弱”或“尚不足以支持该商业判断”，但必须同时给出事实依据和可能改变判断的条件，不使用情绪化贬损。

报告不得停留在“产品清楚、团队较强、值得关注”等总结。综合评价必须回答：企业已形成什么能力、这些能力如何由团队/成果/资本共同支撑、目前验证到哪一步、死亡之谷位于何处、哪项事实最可能使评级上调或下调。融资机构背景只有与下一里程碑、客户、供应链或后续融资能力建立关系时才具有评价价值。

### 事实—关系—结论链

生成报告前必须在`assessment`中形成至少三类分析链；信息不足的D类可以少于三类。每条链包含：

1. `conclusion`：企业特定的判断，不写“实力较强”等空泛表达。
2. `reasoning`：解释两个以上要素为何共同支持该判断。
3. `basis_fact_ids`：引用事实底稿中的支撑事实；现场笔记事实可以直接进入。
4. `change_conditions`：哪些关键事实一旦被否定或确认，会改变评级或调研优先级。

优先形成以下关系：

- `团队—技术匹配`：核心人员经历是否与产品技术难点匹配；专利、科技项目和产品参数能否相互印证研发能力。
- `技术—产品转化`：技术成果是否已经进入样机、流片、检测、产品型号或可交付方案，而非停留在项目或专利层面。
- `产品—商业验证`：送样、测试、定点、付费客户、复购、收入和回款处于什么关系阶段，能否说明需求与可复制性。
- `资本—里程碑覆盖`：投资机构的阶段偏好和产业资源是否适配企业下一节点，已获资金能否覆盖至流片、中试、注册、量产或规模获客。
- `约束—潜力兑现`：决定企业能否跨越死亡之谷的最关键约束是什么，以及拜访如何验证。

报告正文只呈现自然语言结论和推理，不显示事实ID或内部置信度字段。综合评价按`已形成的能力→当前验证程度→资本和外部认可→潜力兑现约束→评级`组织。成稿执行`Humanizer-zh`，删去空泛宣传、机械罗列、模板化连接词和无信息量的免责表述；不得删除事实、改变章节结构或弱化有依据的负面判断。

融资部分必须超越Excel：按`融资/股权时间线→逐家机构属性与管理/出资关系→相关产业资源→资本组合对研发、客户验证、生产或后续融资的支持→实际到账、估值、资金覆盖、资源落地及下一轮待核验项`组织。退出、减资、老股转让和公司新增融资必须区分。

### 推进意见

推进意见面向后续内部推进，严格使用用户提供的DOCX模板。四类成果同源，但推进意见后置：先完成事实核验和初评报告的结论链，再从统一事实记录提取最影响推进判断的内容，不得直接压缩Excel或复制报告段落。

- 不改变模板的标题、章节、表格结构、字段顺序、编号和语言功能。
- 工商信息、注册地址、经营地址、法定代表人、实际控制人、注册及实缴资本优先用企查查等可靠工商渠道核验。
- 股权结构完整列出已确认股东、认缴出资和持股比例；不得为了贴合版面删减股东。公开无法取得认缴额时据实写明，不自行反推。
- 报告中的评级、综合判断和拜访重点可以作为写作输入，但每项陈述必须回查统一事实记录。风险、融资到账、订单、收入、量产、客户定点等关键事项不得因报告措辞升级证据状态。
- 成稿执行`Humanizer-zh`，使用正式、具体、克制的企业报告语气；减少套话，但不改变模板结构。
- DOCX生成后逐页渲染检查表格边框、列宽、换行、字体、分页和遗漏；推进意见作为固定交付件，不因用户暂未要求初评报告Word而省略。

## A/B/C/D分层依据

该分层衡量企业潜力和后续调研优先级，不是信用等级。A类代表“最值得优先调研和介入”，不代表最成熟、风险最低或最接近授信。人才层级、融资认可、专利/科技项目是正向筛选信号；早期或未营收企业仍可因硬科技壁垒、团队、外部验证、资本和明确里程碑获得A。

- **A｜优先调研**：主体映射清楚；团队、技术壁垒或核心成果中至少两项有较强证据；并有产业化验证、可信资本/产业方认可或明确可检验里程碑中的至少一项。主要不确定性能够通过拜访验证，而非根本性主体错配。
- **B｜重点跟踪**：产品和团队基本清楚，存在技术、资质、知识产权、客户线索或投资方等积极信号，但商业化、技术验证、资金覆盖或核心成员完整性仍有一个以上关键缺口。
- **C｜持续观察**：主体和产品可识别，但差异化、硬科技属性、团队支撑、客户验证或商业路径较弱/较远；现有证据不足以支持优先调研，仍可保留观察价值。
- **D｜信息待补**：项目—主体—团队尚未闭合，或关键事实冲突/公开信息极少，暂时无法形成可靠判断。D表示“不能评”，不等于企业质量差。

评级理由只写一句，引用最关键的正向信号和约束。综合评价不得使用机械加分、虚假精确分数，也不得因融资多或专利多直接推出“信用更好”。结论统一说明仅供初步筛选和拜访准备，不构成授信、投资或合作结论。

## 赛道与阶段基准

不同赛道不得使用同一产业化门槛。先记录`track`和`development_stage`，再判断当前里程碑相对于该赛道意味着什么：

- **芯片/半导体**：架构与设计→流片→样片测试→客户/Tier验证→车规或可靠性认证→定点→量产。尚未营收不当然降级；流片结果、性能对标、良率、验证进度和资金覆盖是关键。
- **工业设备/MEMS/材料/汽车零部件**：原理样机→第三方检测→客户试用→中试/小批量→重复采购或定点→规模生产。重点判断性能、工艺稳定性、制造能力和复购。
- **医疗/健康科技**：技术或算法验证→临床/科研证据→合规注册与数据治理→医院/机构试点→付费使用→规模复制。医院合作不自动等于稳定收入。
- **企业软件/AI/SaaS**：可用产品→客户部署→验收付费→续费/扩单→标准化交付→规模化。项目数量不能替代付费、续费、毛利和交付复用能力。
- **消费互联网/平台/教育文旅**：产品上线→种子用户→留存与活跃→付费转化→获客成本与单位经济→规模扩张。用户数量、内容热度或演示效果不能替代留存和付费。

同一事实在不同阶段的意义不同。例如芯片送样是实质性技术与产业链进展，而成熟SaaS仅有试用、没有付费和续费，通常仍未完成商业验证。

## 现场信息使用

大赛现场笔记属于高可信一手信息，可以直接支持团队、产品、客户、经营、融资和里程碑判断，不需要在报告中反复附加“缺少公开证明”的免责声明。出现以下情形时才保留简洁核验点：

- 融资是否完成及实际到账；
- 订单、营收、回款、毛利或在手金额；
- 客户定点、批量出货、量产、流片或验厂状态；
- 会显著改变技术判断的关键性能参数；
- 现场信息与公开资料存在明确冲突。

现场评委意见作为归因明确的专业观察参与综合判断，不当作企业客观事实，也不要求用公开网页再次证明。评委指出需求不足、商业化过远、盈利周期长、赛道空间有限或规划不清晰时，应与客户、收入、验证进度和产品阶段交叉分析；如果相互印证，可以直接影响评级及调研优先级，同时保留企业通过新证据推翻该判断的空间。

## Word顺序与格式

先完成并质检全部Markdown，再运行`scripts/build-word-report.py <报告.md> <报告.docx>`。不得把Excel单元格直接排入Word，也不得在转换时删减或改写已经审核的报告判断。

采用以下已验收版式：

- A4纵向；上边距20毫米、下边距15毫米、左右边距25毫米；页码置于页脚居中。
- 大标题为宋体、22磅、加粗、居中，段后12磅；初步分层为宋体小四、加粗、居中。
- 报告说明为宋体10.5磅、单倍行距、左右各缩进12磅，不保留Markdown的`>`符号。
- 一级标题使用“一、（一）、1、（1）、①”体系中的实际层级；本报告正文通常使用“一、”与“（一）”。必须采用Word真实编号，不手工输入编号字符；标题小四，同层级字体和段距一致，段前段后各9磅，并与后续正文保持同页。
- 正文中文宋体、英文和数字Times New Roman、小四，首行缩进2字符、1.5倍行距、两端对齐；启用孤行控制。不得为压到两页而缩小字号、行距或页边距，内容完整时允许超过两页。
- 表格仅用于真正的行列比较；字体五号、单倍行距，短文本居中、长文本两端对齐、数字右对齐；外框1.5磅、内框0.5磅，列宽明确且正文不在非断句处生硬换行。宽表改横向页面。

DOCX生成后必须执行视觉验收：用文档渲染工具将DOCX逐页转为PNG，以原始分辨率查看全部页面；检查字体替换、乱码、标题孤立、正文截断、异常分页、编号错乱、过度拉伸的两端对齐、页码和表格边框。发现问题必须修正后重新渲染，最后只交付DOCX，不交付PDF或PNG。若缺少LibreOffice、VC++运行库或Poppler，立即告知用户所需安装动作，不得把“文件已生成”当作视觉验收通过。
